# Cage skinning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cage.skin(limbs, { blend?, set? })` poses a subdivision cage from posed limbs with per-point weights worked out for the author, and the cage hand is rebuilt on it.

**Architecture:** A posed limb gains one plain-data field, `bones`, with unrounded rest and posed joint frames. `cage.skin` reads it, works out per-point weights from the rest cage (distance to each limb's rest line, a visibility test, a share per joint), moves the points, and locks the cage. Weights are cached by content. Nothing else in the drag or preview path changes: they only read `snapshot()`.

**Tech Stack:** plain ES modules, vitest. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-23-cage-skin-design.md`

## Global Constraints

- A pose moves the cage's points and never its faces: `snapshot().faces` and `ids` are the same before and after `skin`.
- No point index anywhere in the public API or in an error message. Errors name a limb, a joint or a face id, and say what to change, in the style of the existing `cage:` errors (`fail()` in `src/framework/geometry/subdiv/cage.js`).
- Weights depend only on the rest cage, the limbs at rest, `blend` and `set`. Never on the pose.
- `bones` and the report are plain data (JSON-safe): the cage and the limb can come from two copies of the module, so no WeakMap, no class identity, no function.
- An unknown option key is an error (the limb's and the cage's existing rule).
- Refused in this version, each with its own error: a mirrored cage, a limb with a `parent`, a limb defined without `r`.
- Writing style for comments and docs: plain, short sentences; no CHANGELOG file (release notes go in the commit body).
- Do not bump the package version; that rides with the PR.

## Review Focus

- A point exactly on a limb's rest line (distance 0): the visibility test must not divide by zero or call it hidden.
- Two limbs whose rest lines pass within one radius of the same point with no face between: weights over 1 are shared in proportion, never summed past 1.
- A joint whose next segment has zero length (two joints at one place): the share's direction falls back to the next segment that has length.
- A limb posed at rest (every angle 0): `skin` moves no point at all, bit for bit.
- A `set` entry naming a face that was extruded away: the cage's existing "was extruded" error, not a crash.

**Interfaces:**
- Produces, on every posed limb: `posed.bones = { kind: "partforge.bones", name, parent: boolean, r: number[] | null, joints: [{ name, rest: Frame, posed: Frame }], tip: { rest: [x,y,z], posed: [x,y,z] } }` where `Frame = { origin, x, y, z }`, part coordinates, unrounded. `name` is the limb's name; joint `name` is the full frame name (`"index.mcp"`). `rest` is the limb with every joint at 0 and no pose-level `spread`/`twist`. `r` has `joints.length + 1` entries or is null.
- Produces: `cage.skin(limbs, options?) -> report`, on the object `createCage` returns (so `k.cage` and `partforge/organic`'s `cage` both have it).
- Produces from `skin.js`: `skinWeights(snapshot, bones[], { blend, set }) -> weights` and `applySkin(points, weights, bones[]) -> points` (names are the builder's; the cage calls them).

**The rules** (the spec's, with the numbers a throwaway test used):

- Rest line of a limb: its joints' rest origins in order, then the rest tip.
- Pull of limb L on point p: `d` = distance from p to the rest line, `q` the nearest spot on it, `ρ` = `r` interpolated along the line at `q` (held at the tip's past the tip). `w = 1` for `d ≤ ρ`, falling smoothly to 0 at `d = 1.5ρ`. `w = 0` if the segment p→q crosses any cage face not touching p (split quads into two triangles; ignore hits at the two ends).
- Sum of pulls over 1: divide each by the sum. Under 1: the rest stays on the body (the point's rest position).
- Share of joint j for point p: `smoothstep(((p − O_j) · u_j + b_j / 2) / b_j)`, `O_j` the joint's rest origin, `u_j` the unit direction to the next rest origin (the tip for the last joint; skip zero-length segments), `b_j` the joint's `blend` (default: `r[j]`).
- Motion of joint j alone: `C_j = D_{j−1}⁻¹ · D_j` with `D_j = posed_j · rest_j⁻¹` (rigid 4×4 from the frames; `D_{−1}` is identity). `C_j` fixes `O_j`: read it as an axis and an angle about `O_j`.
- A point's place by limb L: turn it about each joint by `share × angle`, last joint first. Its final place: `Σ w_L · place_L(p) + (1 − Σ w_L) · p`.
- `set` entries apply in order to the points of their faces: `follow` replaces every pull for those points; `turn` replaces the share for the joints it names.

**The lock:** after `skin`, `extrude`, `move`, `scale`, `rotate`, `crease` and `skin` throw `cage: <op> after skin — skin is the last change to a cage`. `centroid`, `normal`, `size`, `faces`, `bounds`, `snapshot` read the posed points.

**The report:** `{ limbs: { <name>: { points, full } }, shared, still, faces: { <id>: { follow: { <limb>: mean pull } } } }`; `faces` leaves out faces whose points are all still. Numbers rounded to 3 places.

**The cache:** a module-level Map in `skin.js`, at most 8 entries, keyed by a string built from the rest points, the faces, each limb's rest frames and `r`, `blend` and `set`. A hit skips the weight work.
